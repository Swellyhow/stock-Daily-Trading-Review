# 竞价工作台数据源与缓存策略

## 数据源

竞价工作台使用同花顺 iFinD MCP 的 A 股服务：

`https://api-mcp.51ifind.com:8643/ds-mcp-servers/hexin-ifind-ds-stock-mcp`

请求通过 `Authorization` 请求头发送 MCP 密钥，采用 JSON-RPC `tools/call` 调用 `sector_data`、`get_stock_summary`、`get_stock_performance` 等工具。页面不再把东方财富竞价数据混入 iFinD 数据集。

## 环境变量

将 51ifind 个人中心中 MCP 配置的 `Authorization` 值写入服务进程环境变量：

```text
IFIND_MCP_TOKEN=你的Authorization值
IFIND_MCP_URL=https://api-mcp.51ifind.com:8643/ds-mcp-servers/hexin-ifind-ds-stock-mcp
```

项目只提供 `.env.example` 模板，不把真实密钥写入版本库。当前运行状态可通过 `/api/auction-management/status` 查看。

## 本地持久化

所有竞价工作台响应按板块、股票、周期、日期写入 SQLite 的 `market_management_cache` 表。页面访问顺序为：进程内存缓存 -> SQLite 持久化缓存 -> iFinD MCP 网络请求。只有显式点击“更新竞价数据”或本地没有对应数据时才访问网络，成功后覆盖对应缓存。

缓存记录包含数据源标识。若 iFinD 请求失败但存在旧的 iFinD 缓存，接口会返回旧数据并标记 `dataQuality: stale-local`；如果没有本地数据则返回 `dataQuality: unavailable`，不使用其他厂商数据猜测填充。

## 页面布局

上排依次为概念板块、板块 K 线、板块分时；下排依次为个股列表、个股 K 线、个股分时。两排之间和每排内部均独立拖拽，布局保存在 SQLite 的 UI 偏好表中。
